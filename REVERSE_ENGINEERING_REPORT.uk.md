## A. Загальний діагноз

### Виявлена архітектура
ehr-common — це спільні компоненти системи на основі openEHR, таких як Clinical Data Repository. Це багатомодульний проєкт Java/Kotlin, збудований на Maven. Розроблений Better Ltd (better.care).

Модулі:
- `ehr-common-amnode` — вузли моделі архетипу
- `ehr-common-jacoco` — покриття коду
- `ehr-common-model` — openEHR Reference Model (RM) і Archetype Object Model (AOM)
- `ehr-common-path` — витяг значень за шляхом (SimplePathValueExtractor, PathSegment)
- `ehr-common-serialization` — серіалізація JSON (Jackson, Kotlin Serialization), XML (JAXB), YAML (Jackson)
- `ehr-common-terminology` — термінологія openEHR (TERM 3.0.0)
- `ehr-common-terser` — стиснення/розпаковка шляху
- `ehr-common-time` — тимчасові типи openEHR (OpenEhrTemporal, OpenEhrOffsetTime, DateTimeConversionUtils)
- `ehr-common-utils` — утиліти

Точки входу: класи моделі (org.openehr.rm.*), серіалізатори (care.better.platform.json.jackson.*), екстрактори шляху (care.better.platform.path.*), тимчасові утиліти (care.better.platform.time.*).

### Деталі

**REA-006 — `locatable.name!!.value` (ПІДТВЕРДЖЕНО)**
- Проблема: `AmUtils.findMatchingNode` використовує `!!` у `locatable.name`. Якщо `locatable.name` дорівнює null, виникає NullPointerException у часі виконання.
- Довід: `AmUtils.kt:516` — `if (locatable.name!!.value == amNode.name)`
- Причина: оператор асертації не-null (`!!`) у виробничому коді без попередньої перевірки null.
- Наслідок: метод може викинути неobроблену винятокinu, коли `locatable.name` дорівнює null, ламаючи відповідність вузлів архетипу.
- Пропонована виправка: замінити `!!` на безпечний доступ до null (наприклад, `locatable.name?.value`) з належною обробкою.

**REA-007 — `propertyMethods!!` (ПІДТВЕРДЖЕНО)**
- Проблема: `SimplePathValueExtractor.getNodeForProperty` використовує `!!` у `propertyMethods`. Параметр є nullable (`? = ConcurrentHashMap()`); якщо null передається явно, виникає NPE.
- Довід: `SimplePathValueExtractor.kt:116` — `propertyMethods!!.computeIfAbsent(...)`
- Причина: використання `!!` на ін'єктованій nullable властивості.
- Наслідок: витяг значень за шляхом може впасти з NPE.
- Пропонована виправка: перевірити null `propertyMethods` або використати безпечний оператор.

**REA-008 — `element!!` у PathSegment (ПІДТВЕРДЖЕНО)**
- Проблема: `PathSegment.getSegment()` та `asPathSegment()` використовують `!!` у `element`, який є `String?` у конструкторі. Якщо null, виникає NPE.
- Довід: `PathSegment.kt:48` і `:58` — `PathUtils.underscorePath(element!!)`
- Причина: `element` оголошений як nullable, але доступний через `!!`.
- Наслідок: побудова шляхів архетипу може впасти з NPE, коли `element` дорівнює null.
- Пропонована виправка: обробити null `element` зі значенням за замовчуванням або безпечною перевіркою.

**REA-009 — `currentLanguage!!` (ПІДТВЕРДЖЕНО)**
- Проблема: обробник SAX `OpenEhrTerminology` використовує `!!` у `currentLanguage` при обробці елемента `concept`. Якщо `concept` з'являється перед `terminology` (який визначає `currentLanguage`), виникає NPE.
- Довід: `OpenEhrTerminology.kt:143` — `terms[TermKey(currentLanguage!!, id)]`
- Причина: порядок елементів XML не перевіряється; `currentLanguage` може бути null.
- Наслідок: парсинг файлів термінології може впасти з NPE.
- Пропонована виправка: перевірити null `currentLanguage` перед використанням.

**REA-010 — Загальний перехват `Exception` із тихим резервом (ПІДТВЕРДЖЕНО)**
- Проблема: `OpenEhrTemporal` перехоплює загальний `Exception` і повертає рядок резерву, маскуючи причину.
- Довід: `OpenEhrTemporal.kt:103-105` — `catch (e: Exception) { return "$temporal [...]" }`
- Причина: занадто широкий блок перехвата без запису винятку.
- Наслідок: помилки форматування часу тихо замінюються резервом, що ускладнює діагностику.
- Пропонована виправка: обмежити перехват конкретними винятками та/або додати логування.

**REA-011 — Порожній перехват `Exception` (swallow) (ПІДТВЕРДЖЕНО)**
- Проблема: `OpenEhrOffsetTime` перехоплює `Exception` у порожньому блоці всередині циклу спроб розбору.
- Довід: `OpenEhrOffsetTime.kt:82-83` — `} catch (e: Exception) { }`
- Причина: виняток гніться без обробки чи запису.
- Наслідок: помилки розбору тихо ігноруються; викидається лише кінцевий `DateTimeException`.
- Пропонована виправка: уникнути порожнього перехвата; записати виняток або обгорнути з контекстом.
